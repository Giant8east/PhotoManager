# PhotoManager 方案设计

## 1. 技术基线

- 平台：Android，当前 `compileSdk 34`、`targetSdk 34`、`minSdk 24`。
- UI：Jetpack Compose + Material 3。
- 语言：Kotlin。
- 架构：UI -> ViewModel -> Data。
- 异步：Kotlin Coroutines + StateFlow。
- 图片加载：Coil。
- 持久化：Room。
- 分页：Paging 3。
- 后台同步：WorkManager。
- 依赖注入：Hilt，项目引入后统一管理依赖。

Repository 不是强制层。只有多个数据源需要协调、缓存同步或事务逻辑明显复杂时，才增加一个薄的 FeatureData 或 Repository。

## 3. 数据流设计

```text
MediaStore / Room
       ↓
Data 映射与归一化
       ↓
稳定的 PhotoItem / FolderItem
       ↓
Feature ViewModel
       ↓
不可变 UiState
       ↓
无状态 Compose Content
```

每个主要页面对应一个 ViewModel。Route 负责获取 ViewModel 和收集状态，Content 通过参数接收状态和事件，子 Composable 不自行创建页面级 ViewModel。

## 4. 核心模型

```kotlin
data class PhotoItem(
    val id: Long,
    val uri: Uri,
    val name: String,
    val folderName: String,
    val mimeType: String,
    val width: Int,
    val height: Int,
    val sizeBytes: Long,
    val modifiedAt: Instant,
    val isFavorite: Boolean,
    val isHidden: Boolean
)
```

`PhotoItem` 是 UI 和业务使用的稳定模型。MediaStore 返回的缺失名称、异常尺寸、未知 MIME 或空路径在 Data 层归一化，不把这些判断扩散到 ViewModel 和 Compose。

## 5. MediaStore 设计

- 使用 `ContentResolver` 查询 `MediaStore.Images.Media.EXTERNAL_CONTENT_URI`。
- 使用 `content://` URI 作为图片身份和加载地址，不依赖易失效的文件路径。
- 查询投影只包含页面需要的字段。
- 使用 `_ID`、`DATE_MODIFIED` 和 URI 做增量同步依据。
- 用 `ContentObserver` 感知媒体库变化，再触发轻量刷新或后台同步。
- Android 13 及以上申请 `READ_MEDIA_IMAGES`；Android 12 及以下申请 `READ_EXTERNAL_STORAGE`。
- Android 14 的部分照片访问权限必须在 UI 中明确展示当前访问范围。

## 6. Room 设计

Room 保存应用自己的业务数据，不保存原始 Bitmap 或完整媒体文件：

```text
PhotoMetadataEntity
- mediaStoreId
- contentUri
- isFavorite
- isHidden
- userNote
- lastSeenAt

PhotoTagEntity
- photoId
- tagId

TagEntity
- id
- name
```

同步时以 MediaStore 为媒体事实来源，以 Room 保存用户产生的整理信息。发现媒体已不存在时，删除无效索引，但可按产品需要保留用户标签历史。

## 7. 删除流程

```text
用户选择图片
  ↓
ViewModel 发出删除事件
  ↓
Data 校验 URI 并生成待删除集合
  ↓
ActivityResult / 系统删除授权
  ↓
用户确认或取消
  ↓
重新查询 MediaStore
  ↓
同步 Room 并更新 UiState
```

批量删除使用 `MediaStore.createDeleteRequest()` 一次提交 URI 集合。ViewModel 不直接操作 `ContentResolver`，也不根据“请求成功返回”臆测文件一定已经删除。

## 8. 状态设计

```kotlin
data class AlbumUiState(
    val isLoading: Boolean = false,
    val photos: List<PhotoItem> = emptyList(),
    val selectedIds: Set<Long> = emptySet(),
    val permissionState: PermissionState = PermissionState.Unknown,
    val errorMessage: String? = null
)
```

状态变化通过明确事件进入 ViewModel，例如 `LoadPhotos`、`ToggleSelection`、`RequestDelete`、`Refresh`。单次导航、授权请求和 Toast 等一次性行为使用 `SharedFlow` 或事件通道，不塞进长期 UiState。

## 9. 组件组合原则

基础图片卡片只负责布局和通用交互；收藏标记、选择状态、标签徽章和尺寸信息通过参数或 slot 组合。避免通过大量 `showXxx` 布尔参数制造万能组件。页面组件保持无状态，便于预览和测试。

## 10. 实施顺序

1. 确认 Gradle、Compose 和 Kotlin 基线。
2. 完成权限状态和 MediaStore 查询原型。
3. 完成分页图片网格和 Coil 缩略图加载。
4. 完成详情页和多选状态。
5. 完成系统删除授权及删除后同步。
6. 接入 Room 收藏、标签和隐藏状态。
7. 增加文件夹、搜索、后台增量同步。
8. 补充测试、性能检查和 README。

## 11. 验证重点

- Android 12、13、14 权限行为。
- 空媒体库、拒绝权限和部分照片授权。
- 一万张以上图片的首屏、滚动和内存占用。
- 单张和批量删除的确认、取消、失败和外部变更。
- 进程重建后 Room 数据与 MediaStore 数据的一致性。
